# sdlc-start（进入需求）

读取用户主目录下 **`.sdlc/skill-core.md`** 并完整遵循——特别是触发映射、plan/apply 协作（§3）与对话输出规范（§0）。

本命令：`sdlc start <URL|id>`（无参 = 恢复/分流）。要点：

- `req_id` 必须来自用户提供的 URL/id，不编造。
- 工作区有未提交改动时，先请用户保存（`sdlc next`）或处理，再切分支——不带脏产物进入新需求（防夹带）。
- 接手时若上游已交接但节点未进入你的阶段，会建议追赶推进到目标阶段（前置未推进节点一并推进），确认后执行；流程入口任务（如「确认进入开发」）不在此勾选——进入阶段且需求子任务拆分完成后才勾。

转述时用自然语言描述（「创建需求分支并绑定、建立本地档案」），用户确认后由你执行 apply；命令与 plan_id 不出现在给用户的文字里。
