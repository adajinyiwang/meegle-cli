# AI SDLC 研发流水线（sdlc-pipeline）使用文档

面向产品 / 研发 / 测试同学的日常使用指南。sdlc-pipeline 是一个 AI Agent Skill：在支持 Agent Skills 的 AI 编程助手（如 Claude Code）里，用 4 个命令把一个飞书项目（Meegle）需求从「开启」驱动到「收尾」——拉分支、传文档、拆任务、转节点，全程有确认、可回读、不猜不跳。

> 相关文档：[meegle-cli 总 README](../README.zh-CN.md) ｜ 命令内部流程见仓库 `skills/sdlc-pipeline/`

---

## 1. 它解决什么问题

标准研发流程里，「需求 → 分支 → 文档 → 节点流转 → 拆任务排期」散落在飞书项目页面、git 命令行和口头约定中。sdlc-pipeline 把这条链路收进 AI 对话：

- **一条命令开启需求**：给一个飞书项目链接或需求编号，AI 完成需求验证、仓库定位、分支拉取/创建、文档目录骨架。
- **一条命令推进一步**：AI 实时查询飞书节点与 git 远端，判断你当前角色阶段的下一个未完成动作并执行（上传文档 / 拆任务估分排期 / 流转节点），一次只推进一个动作。
- **每个写操作都有确认卡片**：push、建远端分支、节点流转，都会先展示摘要卡片，你明确确认后才执行；执行后 AI 会回读验证、如实报告——接口返回 success 不算数。

## 2. 安装与前置条件

**前置**：Node.js ≥ 16（自带 npm/npx）；飞书项目（Meegle）账号。

```bash
# 一键安装（交互式向导：装 CLI + 装三个 skill）
npx @didatravel/meegle@latest install

# 私有化部署可指定 host；无浏览器环境可加 --device-code
npx -y @didatravel/meegle@latest install --host <host> --device-code --lang zh
```

向导会安装：

| 组件 | 作用 |
|---|---|
| `meegle` CLI + meegle skill | 飞书项目查询/流转的底层执行 SOP |
| meegle-sdlc skill | 分支绑定与流转纪律（确认卡片、回读、熔断） |
| **sdlc-pipeline skill** | 本文档的 4 个命令 |

安装后登录并验证：

```bash
meegle auth login      # 浏览器或 --device-code
meegle auth status     # 确认 logged_in
```

**更新**：无需专门命令。运行 `npm i -g @didatravel/meegle@latest`，或跟随 CLI 启动时的更新提示即可；skill 随包同版本更新。

## 3. 命令速览

在 AI 助手对话框中输入（自然语言等价表达同样有效，如「开启这个需求」「下一步」「需求什么状态了」）：

| 命令 | 作用 | 是否写操作 |
|---|---|---|
| `/sdlc-start [链接\|ID]` | 开启需求：验证 → 摘要卡片 → 仓库/分支 → 文档骨架 | 建分支/推送前有确认卡片 |
| `/sdlc-next` | 推进当前阶段的下一个未完成动作（一次一个） | 写操作均有确认卡片 |
| `/sdlc-done` | 收尾核对：列出已完成/未完成清单，不代跳 | 纯读 |
| `/sdlc-status` | 实时状态展示（重查飞书 + git，不依赖会话记忆） | 纯读 |

所有命令**幂等**：完成度以权威源（飞书 `get-node`、git 远端 `ls-remote`）实时判定，重复执行不会重复建分支、重复传文档、重复流转节点——已完成项跳过并说明。

## 4. 典型使用流程

### 4.1 开启需求

```
你：/sdlc-start https://project.feishu.cn/dida/ptproduct/detail/7114275203
AI：（验证需求后展示摘要卡片）
    需求：7114275203 订单导出性能优化
    空间：dida　类型：story
    当前 doing 节点：需求关键信息确认　推断阶段：产品
    （随后定位仓库与本地目录，必要时询问你）
    即将执行分支操作：
      仓库：git@example.com:dida/order-service.git（本地 ~/work/order-service）
      分支：feature/7114275203-order-export（远端不存在 → 从 main 新建）
    确认执行？
你：确认
AI：（建分支、创建 docs/sdlc/7114275203/{prd,cases,reports}/ 骨架并报告）
```

- **不带参数**：`/sdlc-start` 回车后，AI 根据当前目录的 git 状态跟你确认——继续当前分支指向的需求，还是开启新需求（新的再给链接/编号）。
- 本地还没有仓库？AI 会询问仓库地址与路径，征得你确认后 clone。

### 4.2 逐步推进（/sdlc-next）

AI 先实时重查节点与 git 状态，推断你的角色阶段，然后按动作序列取**第一个未完成项**执行：

| 阶段 | 动作序列 |
|---|---|
| 产品 | ① 上传设计文档 → ② 流转【需求关键信息确认】 |
| 研发 | ① 拆任务+估分排期 → ② 流转【确认进入研发】 →（编码/部署，AI 不管）→ ③ 流转【测试环境部署】 |
| 测试 | ① 上传测试用例 → ② 上传测试结果 → ③【测试】节点估分排期 → ④ 流转【测试】 |

每类动作你会看到什么：

- **上传文档**：AI 先**问你**传哪些文件（给文件名或路径；它不会自行扫目录挑文件），复制进对应目录后分别展示**提交确认卡片**和**推送确认卡片**，推送后回读远端验证再报告成功与否。
- **拆任务+估分排期**：AI 读需求描述生成拆分建议表（任务名/职责/估分/起止日期），你确认或修改后才创建子任务并回读；节点排期写入前也有一张确认卡片（排期/估分/负责人）。
- **流转节点**：重查 doing 节点做阶段一致性校验 → 展示流转确认卡片 → 你明确同意（「确认」「执行」）→ 委派执行 → 回读节点状态 → 如实报告。**「收尾吧」「转它」这类模糊指令不构成同意**；流转失败会先诊断必填字段、自动重试最多 2 次，仍失败则熔断转人工说明，绝不虚报成功。

### 4.3 收尾与查看状态

```
你：/sdlc-done
AI：需求 7114275203 订单导出性能优化 收尾核对：
      节点：需求关键信息确认 ✓ ｜ 确认进入研发 ✓ ｜ 测试环境部署 ✗ ｜ 测试 ✗
      文档：prd ✓ ｜ cases ✓ ｜ reports ✗（✓ = 已推送远端）
      任务：子任务 3 个
      分支：已推送；未提交改动：无
    未完成项如实报告，不代跳，并提示对应命令。
```

`/sdlc-status` 随时可跑（纯读、无需任何确认），展示同一张清单 + 当前阶段与下一个动作提示。

## 5. 团队约定（dida）

| 约定 | 当前值 |
|---|---|
| 文档目录 | `docs/sdlc/<需求ID>/prd/`（设计文档）、`cases/`（测试用例）、`reports/`（测试结果） |
| commit message | `docs(sdlc): add <prd\|cases\|reports> for #<需求ID>`（Conventional Commits） |
| 节点映射 | 产品→需求关键信息确认；研发→确认进入研发；部署后→测试环境部署；测试→测试（权威源永远是运行时实时查询） |
| 分支命名模板 / 系统↔仓库映射 | **待团队确认**——未配置期间 AI 会直接询问你（分支名/命名规则、仓库地址与本地路径），你给出通用规则后 AI 会建议写入配置文件（`skills/sdlc-pipeline/references/team-conventions.md`），后续不再询问 |

## 6. 护栏：AI 不会做什么

- **不猜**需求、仓库、分支、节点——定位不到就问你一次，仍无则停止，绝不用模糊搜索「凑一个」。
- **不跳过确认**：push、建远端分支、节点流转，无论多急都先出确认卡片。
- **不虚报**：接口 success ≠ 成功，一律回读验证；未生效按失败报告。
- **不越权**：不扫你的目录挑文档、不动你未提交的改动、`git add` 只加本次动作相关文件、一次只推进一个动作。
- **不跨阶段**：前置节点未流转时拒绝直接转后面的节点，并列出缺失动作清单。

## 7. FAQ

**Q：分支上的需求 ID 和我 start 的需求不一致？**
AI 绝不「就用当前分支凑合」，会按流程重新推导/询问分支名，并在操作前给你确认卡片。

**Q：飞书上的节点名和文档里的默认名不一样（如「需求信息确认（关键）」）？**
AI 用实时查询校验：精确匹配 → 双向包含匹配 → 都不中就列出全部实际节点名**请你指定**，不会猜。

**Q：重复跑了 /sdlc-start 会不会把分支/目录弄乱？**
不会。幂等设计：每一步实时重查权威源，已存在的分支/骨架一律跳过并说明，不重复 checkout、mkdir、commit、push。

**Q：流转返回成功但节点没动？**
AI 以回读为准，按失败处理：先诊断是否有必填字段阻塞，自动重试最多 2 次；仍失败即熔断，给你结构化的根因说明和人工处理建议（页面手动流转 / 找节点负责人 / 联系空间管理员）。

**Q：与 meegle-sdlc（自动流转建议）什么关系？**
互补：meegle-sdlc 是「分支 → 需求」的自动反向建议；sdlc-pipeline 是命令式正向流水线。当会话由 /sdlc-start 驱动时，meegle-sdlc 静默让位，不会出现两套重复的流转确认卡片。

**Q：编码、部署、飞书 IM 通知归它管吗？**
不归。编码/部署由你完成（AI 只在你完成后帮你流转对应节点）；IM 推送由飞书自身自动化覆盖；服务端 dolphin 场景不在范围内。
